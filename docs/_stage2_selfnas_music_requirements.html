1. 背景与问题

SelfNAS 面向个人 NAS 音乐管理与播放，曲库可能从数百首增长到数万首。移动端主要问题是全量加载慢且占用资源、目录筛选不便、歌单与封面体验不统一，以及 Relay 公网、手机缓存和 iPhone 锁屏下的访问与控制不稳定。

项目名称统一为 SelfNAS，不是 Selfless。无封面、锁屏控制、动态公网地址和脚本缓存刷新是本轮必须固定的事实。

2. 产品目标

  1. 让音乐库首屏快速可用，并通过分页、懒加载和增量加载支持大曲库。
  2. 让用户按文件夹快速定位歌曲，筛选、搜索、排序和分页组合时结果可预测。
  3. 提供清晰的歌单页，支持查看、播放单曲及播放全部。
  4. 在本地网络、Relay 公网和 iPhone 锁屏下保持歌曲、封面、播放队列和控制状态一致。
  5. 通过统一视觉与默认封面强化 SelfNAS 品牌识别。

3. 音乐库分页与增量加载

接口采用稳定分页模型，可使用 page/pageSize 或 cursor/limit。响应至少包含 items、hasMore；游标模式增加 nextCursor，total 可选。排序必须稳定：主字段相同时，以歌曲唯一 ID 或规范化路径作二级排序。

首屏只请求填满视口并带少量预加载余量的数据，不等待全量曲库。接近底部时触发下一批请求，推荐使用列表底部观察器。追加加载保留已有内容，失败时可重试。同一条件和页码/游标不得并发请求。筛选、搜索或排序改变后取消无效请求并建立新上下文，禁止混入旧结果。

本轮通过 files.html 给 files.js 增加查询参数，强制刷新手机缓存。每次脚本行为发布都要递增版本参数，并在真机验证请求 URL 已变化。

4. 文件夹筛选

音乐库入口默认显示“全部文件夹”，筛选面板支持展开、收起和选中态。层级较深时显示当前路径；入口可显示摘要，例如“摇滚 / 128 首”。空文件夹显示空状态和返回上级操作，读取失败需区分网络、权限和目录不存在。

筛选条件至少包括 folderId、keyword、sort 和 page/cursor。切换文件夹必须重置分页，从第一页或新游标加载。文件夹筛选应与搜索、排序、分页组合工作。进入歌单或播放器后返回，页面生命周期内可保留条件，但是否跨应用恢复待后续确定。

5. 歌单页面

歌单页包含标题、描述、歌曲数量、封面、播放全部按钮和歌曲列表。首屏优先展示标题与播放入口，列表行高、封面尺寸、加载态应与音乐库一致。

  • 播放全部：按歌单顺序建立队列，从第一首播放。
  • 播放单曲：以当前歌曲为起点，按产品定义继续播放剩余歌曲。
  • 异常歌曲：歌曲不存在或无权限时标记不可播放，不得让整个歌单失败。
  • 交互区域：点击整行播放；更多操作按钮独立处理，避免误触。

歌单排序必须稳定；若支持手动排序，应明确保存顺序、并发编辑和回滚规则。

6. 视觉规范

默认采用可靠、克制的播放器风格，优先保证可读性和播放状态识别。背景、卡片和浮层分层；歌曲名、艺人、辅助信息建立字号层级，歌曲名最多两行。播放中状态不能只依赖颜色，应同时使用图标或文字。

封面统一正方形并懒加载；失败和无封面使用一致降级。底部播放条不得遮挡列表末项，交互需适配安全区、横竖屏和不同 iPhone 尺寸。

7. 默认封面

无封面默认图必须同时使用 黑胶、官方 SelfNAS 图标和完整 SelfNAS 字标，不得出现 Selfless，也不得只显示一个过小图标。SelfNAS 图标需要足够大，保证在列表缩略图、歌单头图和播放器大图中仍清晰可识别；完整字标不得裁切、变形或被背景吞没。

应提供列表缩略图和播放器/歌单大图两种尺寸。资源需有稳定版本路径，允许缓存但能通过版本更新；资源加载失败时应有本地基础降级，不显示破图图标。

8. Relay 公网封面链路

公网客户端不应假定能直接访问内网文件。客户端请求歌曲元数据后，服务端根据当前 Relay 配置、资源路径、用户权限和过期时间生成短期签名 URL，再返回给客户端。客户端只消费 URL，不自行拼接签名参数；长期密钥不得下发浏览器。

签名地址必须动态生成，不能写死 selfnas.local、固定节点 ID 或固定域名。本地和公网应共用同一封面字段协议。URL 过期或返回 401/403 时，客户端重新获取；其他失败回退到默认封面。日志可记录资源 ID、访问模式和状态码，但不得记录完整签名。

推荐链路：客户端请求 → 服务端确认资源 → Relay 生成签名 → 客户端加载 → 过期刷新。需覆盖节点切换、弱网、权限失败、封面不存在和取消请求。

9. iPhone 锁屏媒体控制

播放器接入 iPhone 系统媒体会话，在锁屏和控制中心展示歌曲名、艺人、专辑/封面及播放状态。页面、后台和锁屏控制必须共享单一播放状态，避免状态不一致。

锁屏左右控制必须固定为：左侧 上一曲，右侧 下一曲。不能映射为前进 10 秒或后退 10 秒，也不能按页面状态临时改变含义。队列首尾行为需在实现前固定：上一曲回到上一首或当前曲开头，下一曲在末尾停止或循环，并纳入测试。

切歌后及时更新锁屏媒体信息；后台、断网和恢复网络时队列仍应可控。无封面时使用第 7 节默认图。必须在真实 iPhone 上验证。

10. 技术约束

  1. 兼容移动 Safari，处理安全区、底部播放条、后台恢复和横竖屏。
  2. 歌曲身份由唯一 ID 确定，不依赖 DOM 文本；异步请求处理超时、取消、去重和权限错误。
  3. Relay 地址由服务端运行时配置生成，前端不得硬编码内网域名、固定节点 ID 或固定公网域名。
  4. files.html 中的 files.js 引用必须带可变查询参数，强制刷新手机缓存。
  5. 图片使用懒加载、缩略图和尺寸约束；记录关键事件的结构化日志，敏感签名不得落日志。

12. 已知风险与后续维护规则

12.1 已知风险

  • 曲库实时新增可能影响排序位置，需要快照或版本标记。
  • Relay 节点切换、签名过期和公网抖动可能导致封面短暂失败。
  • iOS 后台策略、媒体权限和音频格式存在系统差异，需真机回归。
  • 默认封面在小缩略图中内容较多，需使用多尺寸资源；缓存未刷新时必须核对脚本 URL、响应内容和缓存头。

12.2 维护规则

  1. 修改分页字段、筛选参数、Relay 签名协议或锁屏映射时，同步更新接口类型、本文档和测试用例。
  2. 新增公网环境不得复制固定域名或节点 ID，统一从运行时 Relay 状态生成。
  3. 默认封面变更必须保留 SelfNAS 完整字标和足够大的官方图标，并回归列表、歌单、播放器三种尺寸。
  4. files.js 行为变更时，递增 files.html 查询参数，并在 iPhone 真机验证。
  5. 锁屏左右语义是高优先级回归项，不得被进度控制、快捷键或第三方适配逻辑覆盖。
  6. 每次发布记录版本号、接口与 Relay 变更、已知问题和回滚方式，确保维护可追溯。
